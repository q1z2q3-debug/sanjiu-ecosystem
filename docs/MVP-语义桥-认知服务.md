# 三元九维 19683 · 认知坐标服务 + 语义桥（5 域全景）

> 目标：把 19683 从「符号库」升级为「Agent 认知引擎」，兑现"既能定位又能泛化"。
> 本版本交付**台阶一（认知坐标服务）+ 台阶二（语义桥·5 域全景 + 深度卦典）**。

---

## 一、核心假设

**"19683 是通用认知坐标"** —— 各领域仓共享同一状态空间，因此**同编号卦的"处境含义"
应跨领域一致**，只是各领域用自己的语言表达。本版把验证从 3 域扩到 **5 域 + 深度卦典**。

## 二、架构（沿「形式统一 + 语义自适配」）

```
sanjiu-core（唯一数学底座，不动）──算子/索引/距离/等价组──┐
                                                          │
服务层 service/bridge.py                                  │
  台阶一 认知坐标原语   encode / search / transform         │
  台阶二 语义桥         fingerprint + 五域规则 + bridge ── 各域 manifest 位权映射
                                                          │
五域解读（同一编号卦，各用本域语言说同一件事）               │
  D/R/T    体用变    洛书九宫    小六壬    疗愈             │
  + 深度象义（主仓人类卦典 19683 全，按 idx 查：卦名/卦辞/启示）
```

- **结构指纹**（跨域共享锚点）：阳/阴/中计数 + 倾向标签（显·进/隐·守/枢·待/偏显·渐/
  偏隐·渐守/衡·中 + 张力高）。
- **位权映射**：各域用自身 `bit_weight_map` 转 core 向量到域内序（正/反向两组）。
- **深度象义**：接入主仓 `sanjiu_quanji_human.json`（19683 条人类卦典），同一编号卦
  附卦名/卦辞/启示 —— 让"回归正轨人类语言解读"落地。

## 三、认知坐标服务原语（台阶一）

| 原语 | 作用 |
|---|---|
| `encode(自然语言) → 9维向量` | 状态写入 19683 坐标 |
| `search(向量, Top-N)` | 欧氏距离邻域定位，附错/综/错综/互/变推演 |
| `transform(卦)` | 全套结构变换 |
| `render(域, 卦)` | 单域确定性解读 |
| `bridge(卦) → 五域解读 + 深度象义` | 同一坐标多语言（核心产品） |

## 四、五域全景演示（确定性，从卦象义长出来）

| 编号 | 卦 | 结构倾向 | 深度象义 |
|---|---|---|---|
| 9841 全中 | (0×9) | 枢·待 | **中·贞吉·察转度卦** — 谋定后动，审时度势 |
| 19682 全阳 | (1×9) | 显·进 | **阳·元亨·启动扬卦** — 乘势而行，主动作为 |
| 0 全阴 | (-1×9) | 隐·守 | **阴·利贞·闭守止卦** — 养晦蓄势，静待天时 |
| 12900 张力 | 阳4阴3 | 偏显·张力高 | **阳·亨·启动度卦** — 顺势而行，戒骄戒躁 |

同一编号卦，**五域 + 深度卦典全部指向同一处境**：

- **全阳卦**：D/R/T"盈·明·丰"／体用变"体厚用盈变现"／洛书"枢纽当行"／小六壬"速喜·吉快"／
  疗愈"体充盈，可疏通"／卦典"乘势而行，主动作为" —— **同判：当进**。
- **全阴卦**：D/R/T"亏·晦·耗"／体用变"体弱用虚变塞"／洛书"枢纽沉寂"／小六壬"空亡·虚耗"／

- **张力卦**：五域都"有攻有阻、矛盾缓进"／卦典"戒骄戒躁" —— **同判：缓进勿躁**。

## 五、一致性验证结果（5 域 + 深度象义）

- **机械一致性：12/12** —— 抽样覆盖全倾向类，每卦五域共享同一结构倾向。
- **深度象义对照：抽查代表卦，卦典（卦名/启示）与五域解读完全同处境**。
- **自然语言定位**：输入"根基稳固，主动进取，增益丰盈，时势顺遂"→ 向量
  `(0,1,0,1,1,0,0,0,1)` → Top1 卦 12353（阳·悔亡·察动度卦），五域解读贴合输入。

## 六、核心假设验证结论

✅ **5 域 + 深度卦典层成立**：同一编号卦在 D/R/T · 体用变 · 洛书九宫 · 小六壬 · 疗愈
五域解读**且深度卦典**都指向同一处境。各域侧重不同（体/承载/中宫/吉凶宫/疗愈维），
是**语义自适配（位权映射 + 域语言）**的应有之义，而非不一致。
"19683 作为通用认知坐标"得到**多域多语言 + 人类卦典三重印证**。

## 八、台阶三雏形 · 邻域泛化推理（generalize.py）

思想：19683 空间是"可定位 + 可泛化"的认知坐标。
**已知处境 → encode 到 9 维向量 → 欧氏距离找最近邻卦 → 借深度卦典启示做知识迁移**。

| 处境 | 向量 | 最近邻卦 | 行动倾向 |
|---|---|---|---|
| 资金有限·想稳步扩张·不冒进 | (0,1,0,1,1,0,0,0,1) | 阳·悔亡·察动度卦 | 审时度势·谋定后动 |
| 长期疲劳·需静养·忌消耗 | (0,-1,0,0,0,1,0,0,0) | 中·贞吉·察转度卦 | 察转·宜养 |
| 行情震荡·多空争夺·应避险 | (0,0,-1,-1,-1,0,0,0,0) | 阴·贞吉·**察守度卦** | **守**·观望避险 |
| 团队争执·需先协调 | (0,1,1,1,0,0,1,0,0) | 阳·悔亡·**启动度卦** | **动**·先调和再进 |
| 产品成熟·市场向好·宜投放 | (1,0,0,1,0,1,0,1,0) | 阳·悔亡·**察动扬卦** | **动扬**·当投放 |

→ 不同处境被自动定位到不同卦、获得对应行动倾向（守/动/察/转/扬）。
**泛化机制成立**：借邻域卦深度象义，对未知/未定状态做可解释的知识迁移。

> 已知限制：`encode` 为纯符号词表，语义分辨率有限（这是"自然语言→向量"编码环节，
> 正是后续与 LLM 混合的落点——LLM 补语义分辨率，符号给可演算骨架）。

## 九、工程化：认知原语包 + CLI + 增强接口

把语义桥封装为**可被 Agent / 脚本调用的认知原语**（兑现"Agent 认知层"落点）：

```
service/  （认知原语包，import service，v0.2.0）
  bridge.py     encode(加权语义打分) / search / transform / render / bridge / deep_oracle
  generalize.py 已知处境→最近邻卦→深度卦典启示（知识迁移）
  enhance.py    增强接口：默认符号骨架 + 可注入 llm_fn（符号给骨架、LLM 填自然语言）
  cli.py        统一 CLI 入口（encode / search / bridge / generalize / enhance / domains）
```

CLI 用法（在 sanjiu-ecosystem 下）：
```bash
cd sanjiu-ecosystem
python3 service/cli.py encode "行情震荡宜避险"        # → 9维向量
python3 service/cli.py search "行情震荡宜避险" --top 3 # → Top-N 最近邻卦
python3 service/cli.py bridge 9841                    # → 编号→五域解读+深度象义
python3 service/cli.py generalize "团队争执需先协调"   # → 邻域泛化推理
python3 service/cli.py enhance "产品成熟宜投放"        # → 符号骨架+泛化总结
python3 service/cli.py domains                        # → 五域清单
```

包调用：
```python
import sys; sys.path.insert(0, "sanjiu-ecosystem")
import service as sb
v = sb.encode("行情震荡宜避险")          # (0,0,-1,-1,0,0,0,0,0)
b = sb.bridge_by_idx(9841)              # 五域解读 + 深度象义
r = sb.enhance("产品成熟宜投放", llm_fn=lambda sk: "…")  # LLM 可注入
```

## 十、LLM 混合主链路（接入即是我自己）

主仓设计哲学：未配置外部 LLM API 时，**由对话主模型（Doubao）当场语义解码**——
"大模型直接接入"接入的就是主模型自身。`service/llm_mix.py` 把这条通道接到语义桥：

```
主模型(Doubao) 当场提供两件事          → 注入本管线
  ① decode_llm(text) → (vector, reason)  encode 分辨率增强（口语/隐含语义，不靠词表）
  ② humanize(骨架)   → 人类自然语言解读    回归正轨人类语言体系
管线: 定位 → 五域解读 → 深度卦典 → 泛化 → 人类解读
```

演示（`python3 service/llm_mix.py`）：

> 处境："项目胎死腹中，团队士气低落，但根基还在，宜收敛蓄力、守中待动"
> 主模型解码 → 向量 `(-1,-1,-1,-1,0,-1,-1,0,1)`，理由"整体阴势敛藏……唯根基仍在而中爻持衡"
> 定位 → 卦 86 **阴·利贞·闭守止卦**（养晦蓄势，静待天时），五域同判"守"
> 主模型人类解读 → "此局阴气盛而敛藏，主守不主发……宜收敛元气、稳住底盘，止损聚气，蓄一阳而待"

→ 同一处境，符号给可演算骨架（向量/卦/五域/距离），LLM（主模型）填自然语言，二者合一。

## 十一、接入 Agent 运行时（agent_tool.py · 认知原语工具）

把语义桥封装为 Agent 可挂载的**工具注册表**（name / callable / desc）：

| 工具 | 作用 |
|---|---|
| `sanjiu.encode` | 状态→9维向量（19683 坐标） |
| `sanjiu.search` | 向量→Top-N 最近邻卦 |
| `sanjiu.bridge` | 编号→五域解读+深度卦典 |
| `sanjiu.fingerprint` | 卦→结构倾向 |
| `sanjiu.decide` | **全链路认知决策辅助**（定位+五域+卦典+行动建议） |
| `sanjiu.domains` | 五域清单 |

Agent 决策示范（`python3 service/agent_tool.py`）——对"生态下一阶段应偏产品落地
还是继续扩张"这个战略处境：

| 通道 | 定位 | 行动建议 |
|---|---|---|
| 纯符号 encode | 阳·悔亡·**察动度卦**·谋定后动 | 机在枢纽未熟，勿躁进 |
| **LLM 注入** | 阳·元亨·**启转度卦**·乘势而行 | 宜乘势主动推进，把握当机，防过亢 |

→ LLM 注入更贴实境（根基/引擎已就绪 → 宜主动作为而非保守），示范了
"Agent 用认知层辅助决策"：桥给结构化认知参考（向量/卦/五域/卦典/倾向），
Agent 结合业务判断给出最终决策。**桥是认知辅助，不替代人/业务判断。**
